CLAUDE SKILLS

Turning repeatable design thinking into reusable workflows

I started building Claude Skills when I noticed I was repeatedly giving AI the same context, frameworks, and instructions. Instead of recreating the workflow every time, I turned the processes I trusted into reusable tools.

The Problem
Good AI output depends heavily on the workflow around it.

Without a defined process, I found myself repeatedly trapped in:

Explain → Prompt → Correct → Re-prompt → Structure → Review

I wanted a more consistent, predictable starting point.

What I Built
DESIGN SYSTEM
Standardize tokens & component architectures

Deconstructs interface screenshots into working components, maps semantic W3C tokens, validates state matrices, and ensures WCAG 2.2 accessibility compliance.

AI UX AUDIT
Audit screenshots and live products

Reviews interfaces for usability, hierarchy, interaction, accessibility, and potential UX issues.

HONESTLY
No vague answers. Just the real answer.

Pushes AI to be direct, distinguish facts from assumptions, acknowledge uncertainty, and avoid confident but unsupported answers.

HONESTLY REVIEW
Review anything like an expert

Provides a structured second perspective for reviewing designs, products, ideas, documents, and other work.

How the Workflow Changed
BEFORE

Repeat the process from scratch.

CONTEXT → PROMPT → CORRECT → REVIEW
AFTER

Reuse workflow and focus on decision.

SKILL → CONTEXT → OUTPUT → DESIGN JUDGMENT
How I Build a Skill

I turn a repeatable design task into a workflow I can reuse, evaluate, and improve.

01 — CONTEXT

Give the Skill the information it needs to understand the task.

02 — PROCESS

Define how it should analyze, reason, and approach the problem.

03 — OUTPUT

Structure the result so it's useful in my actual design workflow.

04 — REVIEW

Check the output against a quality bar and identify where the Skill falls short.

05 — ITERATE

Refine the workflow based on what works, what doesn't, and what I learn.

The Principle: Don't just prompt AI. Build a better workflow around it.

The goal isn't to automate design judgment. It's to make repetitive design work more consistent, reusable, and easier to improve.

MCP (MODEL CONTEXT PROTOCOL)

Connecting the tools around a design problem

Instead of copy-pasting between tool silos, MCP connects research, product specs, and design files into one continuous AI-assisted workflow.

The Problem: Context Fragmentation
Jira (Specs) ⇄ Mobbin (Benchmarks) ⇄ Figma (UI) ⇄ Claude (Chat)

Without connected context, designers spend valuable time repeatedly copying information and re-explaining the same problem to AI from scratch.

The Connected Context Pipeline
01 · JIRA MCP
Product Specs

Requirements, tickets, acceptance criteria & user priorities.

02 · MOBBIN MCP
Market Benchmarks

Flows, interaction patterns & competitive references.

03 · FIGMA MCP
Design System

Components, screen tokens, existing flows & edge states.

04 · MULTI-TOOL SYNTHESIS & DECISION
Specs + Market Benchmarks + UI Context → AI Synthesis → Design Decision

AI surfaces risks, edge cases, and alternatives across all 3 tools. I decide what trade-offs to make and what experience to build.

The Workflow Shift
BEFORE · FRAGMENTED

Tool → Copy → Prompt → Tool → Copy → Prompt

AFTER · CONNECTED

Connected Context → AI Synthesis → Action

The Principle: The value isn't connecting more tools. It's connecting the right context at the right moment.

Jira tells me what we're solving. Mobbin shows market patterns. Figma shows what we've built. AI reasons across them—I make the design decision.

AI UX & TRUST ARCHITECTURE

Designing AI people can actually trust

Most teams treat AI like a conversational novelty. In mission-critical enterprise workflows (legal, medical, and fintech), raw LLM output is a liability unless users can verify, inspect, and audit every single claim with confidence.

The Enterprise Problem: Why Generic AI Chat Fails
01. The Black Box Trap

LLMs state hallucinations with the exact same confident tone as verified facts. Without clear provenance, users waste time second-guessing every sentence.

02. The Cognitive Density Trap

Walls of chat text force professionals into linear reading instead of fast visual scanning, creating decision fatigue.

03. The Workflow Disconnection Trap

AI outputs trapped in sidebar widgets require manual copy-pasting, breaking data integrity and slowing down core workflows.

The 4 Strategic Design Pillars for AI Trust
01 — CONTINUOUS PROVENANCE & TRACEABILITY

Every AI assertion is paired with an interactive inline citation anchor. Clicking jumps immediately to the original source document at the exact line, creating a zero-friction verification loop.

Claim → Evidence Anchor → 1-Click Verification
02 — ADAPTIVE COGNITIVE MODES (DUAL-TIER VIEWPORT)

One size never fits all reading tasks. Users can toggle seamlessly between narrative briefings and granular forensic tables.

Executive Narrative

Fast synthesis for quick high-level briefings.

Deep Audit Mode

Tabular timeline with confidence ratings.

03 — HUMAN-IN-THE-LOOP (VERIFY-BEFORE-SYNC)

AI drafts and proposes data structures; humans maintain complete operational ownership. Batch review actions before committing intelligence to enterprise databases.

✓ Approve ⚑ Flag ✎ Edit ✕ Discard
04 — INTEGRATED OPERATIONAL PIPELINE

Replaced generic chat boxes with embedded pipeline actions that move intelligence directly into the business workflow.

Ingest Raw Data → Cross-Reference → Verify Evidence → Sync to Core System
Design Leadership Principle: The measure of high-caliber AI UX isn't how clever the model speaks—it's how confidently a user can stake their professional reputation on its output.
